# Lot F3 - the browser guest, end to end (notes)

*2026-10-23, branch `feat/remote-f3` (from 84e0d35, F2 merged). Guides: `lot-f2-notes.md` (transport), `lot-f1-notes.md` (web base), `docs/WEB.md` + `docs/fr/WEB.md`, `docs/SHARING.md` + `docs/fr/SHARING.md` (section "join from a browser"). Screenshots: `screenshots/f3/`.*

## Done
- **Link format** (same as the native one, `Link { base, ticket }.to_url()` = `<base>#<ticket>`): `https://<page>/#<ticket>`; `#join=<ticket>` is read too. At start (and on `hashchange`) `platform_web` reads `location.hash`, **removes it with `history.replaceState`**, and queues `Incoming::JoinLink`; `App::join_link_received` opens the "Join a session" window with the link ("Link received") and the name field focused. A link that does not parse opens the same window with the reason and the link editable. A guest without a link uses the existing "Join a session…" menu entry (accepts `inkboard://join#…`, `https://…#…`, bare ticket). The host's name is not in the ticket, so the box cannot say "Join the session of <host>" before connecting: the host name shows once it answered ("Session of <host>", as in the application).
- **Name**: pre-filled from `localStorage` (`inkboard.display_name`, via new `platform::{load_pref, save_pref}`; the desktop keeps its `display_name` file, same behaviour), cleaned by `sanitize_name` on submit.
- **States and errors**: the application's own windows and banners are shared (connecting/waiting, reconnecting, refused, full, bad link, host gone with "Save a copy", enterprise message with 3 tips + "Copy the diagnostic" through eframe's clipboard). Two strings were added (FR in `i18n_fr.rs`).
- **Quick resume**: `platform_web` listens to `online`, `offline` (wake only) and `visibilitychange`; `session_net_web::BrowserNetWatch` (a `NetWatch`) turns them into `retry_now()`; `WebLink::network_changed` calls the new `WebTransport::network_change()` (iroh `Endpoint::network_change`). Native untouched.
- **Images / copies**: F1 had already wired paste (`paste` listener), drop (bytes), downloads (Blob + `<a download>`), "Copy as image"; lot G made guests send images. Nothing duplicated: the bench proves they work in a guest session.
- **Phone**: viewport `maximum-scale=1, interactive-widget=resizes-content`; join/session windows fit the screen width, touch-size (40 px buttons, taller fields) when `pointer: coarse`; session banners wrap and sit under the row of tools; the row of tools **scrolls sideways** on a narrow screen (it was cut off at the edge: tools unreachable on a phone); the guest list sits under it and its "Follow" is a full-size button. (`chrome.rs`: body of the tool row moved into `tool_row`, no logic change.)
- **Start page** (`web/index.html`, `web/initializer.js` as a Trunk initializer): progress bar and size while the `.wasm` downloads, bilingual; messages "too old" (no WebAssembly / WebSocket / BigInt / `crypto.getRandomValues`), "no WebGL nor WebGPU" (before the download), start-up failure with "Reload". No "Safari/Firefox not supported" message: nothing wrong was seen because they were not tried.
- **CI**: job `web` in `ci.yml` (ubuntu, rustup target, `clang lld llvm`, Trunk 0.22.0 pinned by SHA-256, `trunk build --release`, artifact); `pages.yml` (GitHub Pages) **disabled**: `workflow_dispatch` only and both jobs need the repository variable `PAGES_ENABLED=true` (absent). Checked with actionlint 1.7.12. Not run on GitHub (no push): the `web` job is unverified there (clang version of the runner, Trunk tool downloads).

## Not proven / limits
- Not tried: Edge, Firefox, Safari, a real phone or tablet (virtual keyboard, pinch, real touch), the page on a public `https://` host, `web-wgpu`, a real corporate gateway (the "relay blocked" case is Chrome's `--host-resolver-rules`: the browser cannot resolve the relay; a gateway answering 403/407 or a TLS inspection failing is not exercised, and a page cannot read it anyway).
- Phone emulation: Chrome sizes the canvas from the REAL screen pixels, so the phone browsers run with `--force-device-scale-factor=2` and the same emulated factor; with a different one the interface is drawn at the wrong size (emulation artefact, not a page defect, but it means a real device with an unusual DPR/zoom combination was not tried).
- Reconnection timing is logged, not asserted (about 2.5 s to notice a cut, about 1 s to be live again after `online` here); the effect of the `online` listener versus the pauses of the backoff is not isolated by a test (puppeteer's offline emulation both cuts and restores the socket; the listener path itself is exercised: the event is sent and the guest resumes).
- A hidden tab draws no frames: the session sleeps until the tab is visible (listener added for the return, not tested with a real hidden tab).
- The loading bar: with a server that compresses, `Content-Length` is the compressed size while the stream counts unpacked bytes, so the bar stops at 99 % and the text shows only the size received (the bench server does not compress, so that path is not exercised).
- The `web-test` bench build is 21.8 MB raw; the published page 18.14 MB (4.70 MB brotli).
- Clipboard (`Copy the diagnostic`, `Copy as image`) needs a secure context (https or localhost) and the user's permission in some browsers; the bench grants it.

## Pitfalls / decisions
- The e2e bench must run with `--lang=en-US` (set in the script): the machine's Chrome is French by default and the page picks its language from `navigator.language`.
- `press()` in the bench waits for two equal positions of a widget in a row: windows resize when their content changes (e.g. "Checking the connection…").
- Relay hostnames end with a dot in links (`….iroh.link.`): a blocking rule must list both spellings.
- `page.mjs` (F1) is unchanged and still passes on the new page (see below).
